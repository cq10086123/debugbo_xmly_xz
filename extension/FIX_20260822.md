# 修复记录：官方源报错丢失 + 重试失效 + 账号轮动 + 取消复活

修复时间：2026-08-22 18:20 ~ 18:35（两轮）

## 第一轮（18:20）

### 问题 1：官方源下载失败看不到原始报错
`resolveOfficialRotation` 把非限流错误也 catch 后静默换账号，原始 ret/msg 丢失。

### 问题 2：点重试没反应
done 任务不改回 running，调度器只派发 running → 失败集永远不下载。
- retryFailed / retryAllFailed：`if (task.status !== 'done')` → `if (has)`
- popup.js：重试按钮 `t.status !== 'done'` → `t.status !== 'cancelled'`

## 第二轮（18:35，深度审查下载/轮动/重试链路后）

### 问题 3：retryAllFailed 旧索引快照覆盖（真凶）
`retryAllFailed` 循环结束的 `await setIndex(idx)` 用**循环前旧快照**覆盖了
`setTaskAndUpdateIndex` 已写回的 running 状态 → 重试后索引仍 done → 仍不派发。
**修复**：删除循环末尾的 `await setIndex(idx)`。

### 问题 4：账号轮动被第一轮修复破坏（回归）
第一轮把非限流错误改成直接 `throw e`，导致账号轮动失效（某账号 cookie 失效本该换账号）。
**修复**：恢复轮动（所有错误都换下一个账号），但用 `errors[]` 收集每个账号原始报错，
循环结束用 `errors.join(' | ')` 汇总抛出 → 既保留轮动，又能看到真实失败原因。

### 问题 5：retryAllFailed 复活已取消任务（预存 bug）
`cancelTask` 把 pending/downloading/resolving 集标 `error='已取消'`，任务标 `cancelled`。
`retryAllFailed` 没过滤 cancelled，会把这些「已取消」集重置 pending、任务改 running → 取消的书复活重下。
**修复**：
- retryFailed：`if (task.status === 'cancelled') return`
- retryAllFailed：`if (item.status === 'cancelled') continue`
