# 修复记录：第一本下完第二本不接力 + 全局开始报「卡密已有下载任务」

修复时间：2026-08-24  
插件版本：0.7.0 → 0.7.1

## 现象

- 队列里两本书：第一本 100/100 已完成，第二本 0/68 待处理
- 第一本下完后第二本不会自动开始
- 点「▶ 开始下载」或「立即下载全部待处理」报：
  `操作失败：插件后台无响应（当前卡密已有下载任务进行中，请等待完成后再开始下一本）`

## 根因

全局下载槽是 `claim → heartbeat → complete/cancel`。最后一集结束时 `finalizeTask` 先把本地 `status` 标成 `done`。

旧 `tickClaim` 见到 `done` 只清本地 `claimState`，**不调 `/complete`**，服务器槽仍被第一本占用。下一本 claim → 409。

另外：

- 书完成后没有立刻 `tickClaim`（只靠 1 分钟 alarm）
- 「全部下载」claim 成功第一本就把 `claimPending` 清掉，`autoDownload=false` 时不会接力
- popup `swCall` 把业务 409 包装成「插件后台无响应」

## 修复

1. 本地 `done` / 全终态必须先 `complete` 释放槽，再 claim 下一本
2. 最后一集结束立刻 `scheduleClaimNext`
3. `claimPending` 等到 pending 队列空才清
4. 自愈：本地已完成但仍挂着 `claim_id` 的孤儿任务，补一次 complete（覆盖已卡住的用户）
5. `handleClaimLost` 不再把本地已完成的书打回 pending
6. 槽忙时排队而不是对用户抛错；取消当前书后立刻接力
7. popup 业务错误直接展示原文

## 已卡住用户怎么恢复

在 `chrome://extensions` 刷新本插件（加载 0.7.1）后：

- 若第一本本地记录还在（不要先点「清空已完成」），刷新后会自动 complete 释槽并开始第二本
- 若已经清空，等约 5 分钟租约过期，再点「开始下载」
