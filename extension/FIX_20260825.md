# 修复记录：Mac 用户反馈「每一集都要手动保存」

修复时间：2026-08-25
插件版本：0.7.1 → 0.7.2

## 现象

- Windows 上使用正常，音频自动保存到下载目录
- 多位 macOS 用户反馈：每一集都弹出「另存为」窗口，必须手动点保存，点完一集才轮到下一集

## 根因

**不是插件的代码 bug，而是 Chrome 的用户设置**：`chrome://settings/downloads` 里的
**「下载前询问每个文件的保存位置」** 被开启了。

- Mac 版 Chrome 较常默认开启该开关（macOS 下载习惯是每次询问保存位置），Windows 默认关闭 → 所以只有 Mac 用户反馈、开发者自己在 Windows 上复现不出来
- 该开关开启时，即使扩展用 `saveAs: false` 调用 `chrome.downloads.download()`，Chrome 仍会逐集弹出「另存为」窗口；不点保存，下载项停在 `in_progress` 且 0 字节，队列整体卡住，30 分钟后被判定超时
- 这是 Chrome 故意保留的用户控制项（安全设计），**任何扩展都无法用代码绕过/关闭它**
- 次要因素：macOS Sonoma 起若下载位置设为 iCloud 云盘同步目录，文件还可能被标为隐藏

## 修复（0.7.2）

1. `background.js` 增加平台检测（`chrome.runtime.getPlatformInfo`）
2. 后台每分钟轮询时检测「下载中但持续 0 字节 > 90 秒」的典型卡住症状（Mac 且并发 ≤3 时），弹一次系统通知，引导用户关闭该设置（按 downloadId 去重，下载终止即清除）
3. 单集 30 分钟超时的错误信息附带排查指引（Mac 上直接写明关闭该开关的路径）
4. `popup` Mac 专属一次性提示条（可关闭，状态存 `chrome.storage.local`）：
   - 「打开 Chrome 下载设置」按钮直接跳 `chrome://settings/downloads`
5. `popup` 任务列表实时检测：某集下载中但 0 字节超过 60 秒（且并发 ≤3，排除 Chrome 排队场景），在任务区和该集行内显示「可能在等『另存为』手动保存」提示
6. 网页端「使用说明」FAQ 与 README 增加该问题的排查条目

## 用户侧解决办法（客服话术）

打开 Chrome 地址栏输入 `chrome://settings/downloads`：
- 关闭「**下载前询问每个文件的保存位置**」
- 若「位置」是 iCloud 云盘/同步目录，改回本机「下载」文件夹

改完即可自动保存，无需再逐集点保存。
